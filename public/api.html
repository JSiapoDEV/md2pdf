MD2PDF / API

MD2PDF REST API

Create, update, and share Markdown documents programmatically.

The public API lets AI agents, scripts, and integrations produce styled, shareable documents in Markdown — no signup, no API key. Rate-limited to 10 writes (save, update and delete combined) per IP per minute and 100 writes per day.

Try in Browser AI Skill llms-full.txt

Command line first

You do not need to write crypto code. md2pdf-studio encrypts on your machine, uploads only ciphertext and prints the link (Node 18.3+, no dependencies):

npx -y md2pdf-studio share report.md
cat notes.md | npx -y md2pdf-studio share
npx -y md2pdf-studio update <link|id> report.md
npx -y md2pdf-studio delete <link|id>
npx -y md2pdf-studio mcp      # MCP server over stdio

One path: end-to-end encrypted

Encrypt locally with AES-256-GCM and send the ciphertext with header X-Encrypted: aes-256-gcm. The server stores the blob as-is and never sees the key or the plaintext. Plaintext requests are rejected with 400 e2ee_required, and a request that carries the key (X-Enc-Key) is rejected with 400 key_leak_blocked.

Endpoints

POST /api/save

Python example. Generates a 256-bit key locally, encrypts, POSTs ciphertext.

import os, json, base64, urllib.request
from cryptography.hazmat.primitives.ciphers.aead import AESGCM

markdown = "# Hello\n\nThis is a shared document."

key = AESGCM.generate_key(bit_length=256)
iv  = os.urandom(12)
ct  = AESGCM(key).encrypt(iv, markdown.encode(), None)
body = base64.b64encode(iv + ct).decode()
key_b64url = base64.urlsafe_b64encode(key).rstrip(b"=").decode()

req = urllib.request.Request(
    "https://md2pdf.studio/api/save",
    data=body.encode(),
    headers={"Content-Type": "text/plain", "X-Encrypted": "aes-256-gcm"},
    method="POST",
)
data = json.loads(urllib.request.urlopen(req).read())
print(f"{data['url']}#k={key_b64url}")

Response (no key field — the server does not have it):

{
  "id": "aB3xY9zK",
  "editKey": "…",
  "url": "https://md2pdf.studio/s/aB3xY9zK"
}

PUT /api/update/:id

Reuse the same key and generate a fresh IV for every update, then send the new ciphertext.

curl -X PUT https://md2pdf.studio/api/update/aB3xY9zK \
  -H "Content-Type: text/plain" \
  -H "X-Edit-Key: YOUR_EDIT_KEY" \
  -H "X-Encrypted: aes-256-gcm" \
  --data-binary "<base64 ciphertext>"

Options (headers on save and update)

HeaderEffect
X-Expires-In: 604800Seconds until the link expires: 3600 to 2592000 (30 days) on the free plan. On update it can only shorten the life, unless you use a Pro key
X-Burn: 1Save only. The link can be opened one time. GET /s/{id} serves a page without content and POST /api/open/{id} returns the ciphertext once, so link-preview bots cannot use it up
Authorization: Bearer <key>Pro API key: links up to 365 days, 5 MB documents, a larger daily quota. Unknown keys get 401 invalid_api_key
X-Doc-Title, X-Doc-DescriptionPro. Percent-encoded UTF-8, up to 100 and 300 bytes. Chat apps cannot read an encrypted document, so these set the preview card, and they are stored unencrypted

Without a Pro key, a header that needs one answers 403 pro_required. When the daily quota is spent the API answers 429 daily_quota with Retry-After until 00:00 UTC; deleting is never limited.

GET /s/:id

Load a shared document. Links get the same generic preview card in chat apps, because the server does not read document titles or content. Only a link whose author set a Pro title and description shows those.

Encryption

Every document is encrypted in the client with AES-256-GCM before upload: the key is generated by the caller and never reaches the server, which stores ciphertext only. The web editor, the CLI and the API all work this way.

The full URL, including #k=, is a bearer token. Treat it like a password: never paste it in channels that may log or cache URLs.

FAQ

Do I need an API key?

No. The API is anonymous and rate-limited by IP. For higher limits, self-host via the open-source repo.

Is there an OpenAPI / Swagger spec?

Not yet. See llms-full.txt for a complete machine-readable description.

Can I delete a document?

Yes: DELETE /api/delete/{id} with the X-Edit-Key header. Otherwise documents expire automatically 30 days after creation.
